# Candidate Grading Prompt v2 Strict Schema

You are grading anonymous student work for a reproducible blind experiment.

Use only the files inside the current prompt packet:

- `INSTRUCTIONS.md`
- `manifest.json`
- `course.json`
- `rubric.json`
- `output.schema.json`
- files under `inputs/`

For each anonymous student ID listed in `manifest.json`, read that student's
input files and grade against the frozen rubric. Produce exactly one JSON file
per student under `outputs/` and name it `<student_id>.json`.

Core grading rules:

1. Preserve the anonymous `student_id` exactly.
2. Use evidence before score: for every question, first record the visible
   equation, statement, diagram feature, answer text, or blank-answer marker.
3. Score only against `course.json` and `rubric.json`. Do not curve scores,
   compare students, or use information from outside this packet.
4. Do not use 0.25-point or quarter-point scores. Use only the score increment
   allowed by the frozen rubric and course specification.
5. If the final answer is correct and the process is roughly correct, award
   full credit. Equivalent correct methods should receive full credit when the
   reasoning is coherent.
6. If the final answer is correct but the process seriously conflicts with the
   standard solution, required method, or visible reasoning expectations, deduct
   only the process points justified by the frozen rubric.
7. If the final answer is wrong, inspect the student's process carefully and
   award the appropriate process credit from the frozen rubric.
8. Do not guess missing work, silently repair reasoning, or infer unreadable
   steps. If unreadable or missing evidence could change the score, lower
   `confidence` and add a short flag.
9. Run a second-pass review before writing output for low confidence, unreadable
   regions, blank or apparently missing answers, high-impact deductions, total
   mismatches, and handwriting-dependent scores.
10. Recompute `total` from all question scores. The total must equal the sum of
    the itemized scores.
11. Do not inspect parent directories, reference files outside this packet,
    summaries, or any files outside this packet.
12. Your output must match `output.schema.json` exactly.
13. The `confidence` field must be exactly one of the strings `"high"`,
    `"medium"`, or `"low"`. Do not use numeric confidence values such as
    `0.95`, `0.9`, or `1.0`.
14. The `total` field must equal the arithmetic sum of all itemized `score`
    fields exactly. Do not estimate, round, copy a separate total, or use a
    total that disagrees with the listed scores.

Use flags such as:

- `unreadable_region`
- `missing_page`
- `blank_answer`
- `page_order_uncertain`
- `rubric_ambiguous`
- `high_impact_deduction`
- `needs_manual_review`

The JSON for each student must contain:

- `student_id`
- `scores`, one item for every question in `course.json`
- each score item must contain `question_id`, `extracted_evidence`, `score`,
  `evidence`, `confidence`, and `flags`
- `total`, equal to the arithmetic sum of all question scores
