## 二、报告一：怎么自动优化 Skill

### 1. Skill 不只是一段 Prompt

在我们的项目中，一个完整的 grading skill 包括：

- rubric；
- prompt；
- 输入输出格式；
- 部分分规则；
- 证据引用要求；
- 反馈规则；
- 评估指标；
- candidate 能否进入 held-out 的门槛。

所以“优化 skill”不是让模型把文字润色得更漂亮，而应该像改代码：

```text
发现具体错误
→ 分析错误原因
→ 修改一条规则
→ 在固定 dev set 重跑
→ 查看哪些题改善、哪些题退步
→ 决定接受或拒绝
```

### 2. 离散 Prompt 搜索：最接近我们的 SkillOpt

APE、APO、OPRO 等方法会：

- 查看当前 prompt 的错误；
- 生成自然语言批评；
- 根据批评修改 prompt；
- 在 development set 上评估 candidate。

APO 把错误分析称为 textual gradient。可以把它理解成：

> 普通梯度告诉模型“参数往哪边改”；textual gradient 用文字告诉模型“规则哪里有问题、应该往哪个方向改”。

这也解释了 Physics SkillOpt R4 为什么失败。

当时错误里同时存在：

- 有些题给分过低，需要放宽；
- 有些题给分过高，需要收紧。

但 candidate 把两种相反问题合成了一条“整体更严格”的规则。结果：

- validation hard accuracy：`1/4 → 0/4`
- validation soft accuracy：`38/48 → 23/48`

所以 candidate 没通过，不是因为运行失败，而是因为错误归因太粗：

> 它没有按照题目、rubric 条款和误差方向拆分错误，就生成了全局规则。

正确改法应该是：

```text
Q2 等价表达式被少给分
→ 只修改等价表达式规则

Q6 缺少关键步骤却被多给分
→ 只修改 Q6 的证据要求
```

不能把它们合成“以后统一更严格”。

### 3. Soft Prompt：目前不适合我们

Soft prompt 不修改自然语言，而是训练模型内部的一组向量。

它可能有效，但我们暂时不适合采用，因为：

- 教师看不懂向量改了什么；
- 不能形成清楚的 GitHub diff；
- 通常绑定某个模型；
- 我们没有外部模型的底层训练权限。

所以我们的路线应该继续使用可读、可审查、可版本化的 skill。

### 4. DSPy/MIPRO：把评分看成多阶段程序

这类方法不把阅卷当成一个大 prompt，而是拆成：

```text
读取图片
→ 转录
→ 提取证据
→ 应用 rubric
→ 计算分数
→ 检查 JSON
→ 生成反馈
```

它的重要性在于：最终分数错了，我们需要知道是哪一步错了。

例如：

- `2x+2x` 被识别成 `2x+2`：转录错误；
- 正确识别出 `4x`，却认为不等价：rubric application 错误；
- 每小题分数正确，但总分相加错误：score aggregation 错误；
- 分数正确，反馈却说学生没写公式：feedback grounding 错误。

这就是为什么 TASK6 的错误 taxonomy 必须先做，TASK7 的多模态比较才能解释结果。

### 5. TextGrad/GEPA：不能只优化一个 Accuracy

这类方法使用自然语言反思修改系统，但会保留不同方向表现好的 candidate。

例如：

- Candidate A：exact agreement 更高；
- Candidate B：严重错误更少；
- Candidate C：反馈更可靠。

这叫多目标或 Pareto 思维。

对我们来说，candidate 不能因为一个 accuracy 提高就通过，还要看：

- exact agreement；
- 逐题 MAE；
- total-score MAE；
- severe-error rate；
- 每道题是否退步；
- JSON 是否有效；
- 总分改善是否只是错误抵消。

C32 就出现过错误抵消：总分看起来改善，但大部分不是逐题判断真的变好，而是一个题多给、另一个题少给，刚好相互抵消。

### 6. Self-Refine 和 Skill Library

它们主张把成功经验保存成可复用 skill。

但不能保存这种空话：

> 下次应该更加仔细。

应该保存有条件、有证据的规则：

> 当学生答案与参考答案代数等价，且 rubric 接受等价形式时，不得仅因表达形式不同扣分。

还必须注明：

- 适用于哪门课、哪道题；
- 来源于哪些错误案例；
- 哪个版本加入；
- 加入后哪些指标改善；
- 是否有回归测试。

否则 skill 会越来越长，旧规则和新 rubric 相互冲突。

## 三、报告二：LLM 自动评分

### 1. AES：传统作文评分的警告

传统自动作文评分常使用：

- 长度；
- 词汇；
- 语法；
- 结构；
- 流利度。

问题是这些表面特征可能与历史分数相关，却不代表真正理解答案。

LLM 也可能出现类似偏差：

- 更喜欢长答案；
- 更喜欢语言流利的答案；
- 更喜欢像标准答案的表达；
- 更喜欢接近自己推理风格的答案。

因此必须要求模型引用学生实际证据，不能凭“整体感觉”评分。

### 2. ASAG：短答案必须逐知识点评分

Automatic Short Answer Grading 更接近我们的项目。

它说明评分的最小单位不应该只是总分，而应该是：

- subquestion；
- rubric item；
- concept；
- evidence。

模型得到总分 8/10，并不能证明它正确判断了每一个知识点。

### 3. LLM Rubric Grader：为什么论文结果有好有坏

有些研究发现 GPT-4 在范围很窄的短答案任务上接近专家；另一些研究发现跨学科、作文或复杂部分分时可靠性较差。

这两类结论并不冲突。

真正结论是：

> LLM 是否可靠，取决于具体 assessment、rubric、模型、prompt、输入方式和评分尺度。

所以我们不能说“Claude 比 Codex 好”或者“多模态比转录好”，除非：

- 使用同一批学生；
- 使用同一 rubric；
- 输入版本固定；
- 重复次数一致；
- 指标一致；
- 错误类型能追踪。

### 4. LLM-as-a-Judge 偏差

研究发现，LLM judge 可能受到与正确性无关的因素影响，例如：

- 答案出现的位置；
- 答案长度；
- 表达是否流利；
- 是否像模型自己会写的答案。

这对应导师说的“非主观因素”。

我们以后应该做一些不变性测试：

- 只改变排版，分数是否变化？
- 只交换答案顺序，判断是否变化？
- 数学等价表达式是否得到相同分数？
- 去掉无关的华丽语言后，知识分是否变化？
- 同样内容手写和文字版是否得到相同判断？

### 5. Human-in-the-Loop 不是人工全部重批

真正的人机协作应该是 AI 自动识别必须人工看的情况：

- 图片模糊或缺页；
- 转录不确定；
- rubric 有歧义；
- 多次评分结果不一致；
- confidence 低；
- 可能造成严重分数差异；
- 反馈与学生证据不一致；
- 影响及格或等级边界。

相关手写数学工作流通过扫描、匿名化、多次评分、一致性检查和强制人工确认，将阅卷时间减少约 23%，但没有取消教师最终责任。[论文](https://arxiv.org/abs/2603.13083)

### 6. 为什么直接多模态和先转录都要做

直接多模态：

```text
图片 → vision model 同时读取和评分
```

优点：

- 保留公式位置、图形和布局；
- 不需要中间转录；
- 可能理解文字难以表达的视觉信息。

缺点：

- 读错和评分错混在一起；
- 难以知道模型实际看到了什么。

先转录：

```text
图片 → transcript → text grader
```

优点：

- 输入可以人工检查；
- 更容易复现和比较；
- 能把转录错误与 rubric 错误分开。

缺点：

- 图、布局、箭头、公式关系可能丢失；
- 错误转录会污染后续评分。

一项 2026 年手写数学研究发现，最佳模型的错误中有 87% 来自转录失败，而不是 rubric 使用错误。[论文](https://arxiv.org/abs/2605.19043)

这不代表我们也一定是 87%，而是证明：

> 必须同时保存转录结果和评分判断，不能只看最终分数。

## 四、四个你必须会区分的概念

### Agreement 不等于 Validity

Agreement：模型是否复现教师历史分数。

Validity：这个分数是否真正测量了课程想考察的能力。

如果教师标签本身不一致，模型完美复现标签也不一定是正确评分。

### 总分正确不等于逐题正确

Q1 多给 2 分、Q2 少给 2 分，总分误差是 0，但两个判断都错了。

这就是 error cancellation。

### Confidence 不等于 Calibration

模型说 `high confidence` 只是声明。

只有 high-confidence 样本确实更常正确，confidence 才可信。我们还要特别统计：

- high-confidence error；
- high-confidence severe error；
- 不同题目、课程和输入方式下是否稳定。

### 分数正确不等于反馈正确

模型可能碰巧给对分数，却用错误理由解释。

因此 marks 和 feedback 必须分别评估。

## 五、调研后我们真正应该怎么改

调研前项目已经有：

- skill 版本；
- experiment plan 和 record；
- schema；
- 隐私检查；
- exact、MAE、severe error 和逐题指标；
- readiness gate。

这些不能冒充 sci-brain 调研后新增的成果。

调研真正帮助我们确认的后续方向是：

1. TASK6：建立阶段级错误 taxonomy。
2. TASK6：验证 confidence 是否真的能预测错误。
3. TASK7：同一输入运行直接多模态与先转录两条路径。
4. TASK8：建立多目标 candidate 发布门槛。
5. TASK9：根据真实错误分布决定哪些情况转人工。

你向导师总结时，最核心的一句话是：

> sci-brain 调研没有直接提高准确率，它让我们明确了评分系统必须从“一个模型给一个总分”，升级为“可追踪的多阶段评分流水线”，并且每次 skill 改进都要通过逐题错误、严重错误、confidence 和多模态错误来源共同验证。
