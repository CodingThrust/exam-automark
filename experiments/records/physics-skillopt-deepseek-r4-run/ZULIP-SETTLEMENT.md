negative_result

Goal:
Explain why the Physics Week 9 SkillOpt candidate did not pass, what was wrong
with it, and what must change before another run.

What was done:
- Audited the seed and candidate skills, optimizer patch, gate implementation,
  validation results, held-out results, and item-level private artifacts.
- Separated candidate-policy failure, target-output failure, metric weakness,
  and repeat-evaluation variation.

Evidence:
- experiments/records/physics-skillopt-deepseek-r4-run/FAILURE-ANALYSIS.md
- experiments/records/physics-skillopt-deepseek-r4-run/RESULT-SUMMARY.md

Key result:
The candidate appended one global rule requiring every criterion-specific step
to be explicitly visible. It was generated by incorrectly merging one
under-score and one over-score into the same failure cause. On validation, hard
accuracy fell from 1/4 to 0/4 and soft exact-subquestion accuracy fell from
38/48 to 23/48, so the gate correctly rejected it.

Failure causes:
- Opposite-direction training errors were merged into one one-directional edit.
- The edit over-generalized a local missing-evidence correction and became too
  strict.
- One candidate validation call exhausted 12,000 completion tokens and returned
  empty output.
- Four-student all-questions-exact hard accuracy was too coarse, and only one
  target call was used per condition.

What improved:
- R4 completed the end-to-end SkillOpt loop and 47/48 result records were
  parseable, substantially improving on R3's output reliability.
- The validation gate prevented the harmful candidate from becoming the
  selected skill.
- We now have concrete requirements for direction-aware reflection,
  policy-conflict checks, paired repeat evaluation, and separate reliability
  gates.

How this helps the project:
It prevents us from claiming a false accuracy improvement and turns a vague
"candidate did not pass" into testable pipeline changes for safer skill
optimization.

Limitations / prohibited claims:
- R4 did not improve grading accuracy.
- The held-out hard delta of -0.0556 is not a candidate effect: the candidate
  was rejected, and the same initial skill was evaluated twice.
- A single validation call cannot isolate the causal effect of one prompt edit.

Decision needed:
A. Close R4 as a negative result and move on.
B. Repair the measurement/candidate gates before R5.
C. Combine those safeguards with a narrow criterion-level SkillOpt proof of
   concept.
Recommendation: close R4 now; if a positive SkillOpt result remains required,
combine B and C.

Next action:
Do not rerun R4 unchanged. Decide whether SkillOpt is still required; if yes,
implement the offline R5 safeguards before any paid model call.
